# 飞控分阶段测试路线图

> 目标：把 `flyctrl` 的调试拆成**串行、可交付、可回退**的阶段。每个阶段只攻一个
> 模块，前序阶段全绿后，才允许进入下一阶段。
>
> 本文是排期依据。每条测试都要求：**明确被测模块 / 明确隔离手段 / 明确输入 /
> 明确指标阈值 / 明确失败归因**。

---

## 0. 两个场地（是"场地"之分，不是"能力等级"之分）

| | H 场（`fly-sim-core`） | M 场（`mcu_simulater`） |
|---|---|---|
| 算法在哪 | `flyctrl-core` 同一份源码，主机原生调用 | 同一份源码编译成 Thumb，Unicorn 指令级执行 |
| 单步编排 | `flyctrl_core::hil::HilContext::step_hil` | **同一份** `step_hil` |
| 传感器怎么进来 | `SensorModel` 直接产出结构体 | 真值 → 虚拟寄存器/字节流 → 固件**真实 I2C/UART 驱动** |
| 时序 | 测试按 dt 循环 | RTOS 调度 + `delay_until` 4ms 节拍 + seqlock |
| 约束 | 无 | 栈 20K、CPU 预算、内存布局 |
| 速度 | 快 | **≈7.9× 慢于实时**（实测：60s 场景 = 7:54） |

**原则**
- 算法/参数对不对 → **H 场**（快，可跑扫描/蒙特卡洛）。
- 真实驱动/RTOS/指令级下还对不对 → **M 场**（慢，权威）。
- `flyctrl/sim`（`Harness`）**不是** H 场：它 `estimator.step()` 与 `controller.control()`
  分开调，**绕过了 `step_hil`**（会漏掉 IMU 陷波/低通、FDIR 闸、setpoint 有效性），
  仅 `flyctrl/bin`（SITL CLI）在用。本路线图不用它。

> 注：M 场的物理与传感器**也是模型**（`PhySdkWorld` / `SensorModel` / `EnvScenario`），
> 所以 M 场 ≠ 真机。第三场（地面站 + 实飞）不在本路线图内。

### 解除阻塞的过程

原始阻塞依据（`docs/stage4-outer-loop-findings.md` P17）是：

> M 场对**代码布局极其敏感** —— 同一底座、同一测试，仅是给控制环加一条
> **从不执行**的条件分支，`x_hover_noise` 就从 20.00°/28.64°变成 68.41°/23.35°；
> 无条件写一个 16B 诊断量则变成 141.90°/87.38°（发散）。

**根因已定位并修复（≥2026-09-21）**：不是“固件没有时序余量”（那个归因建立在
虚高 1.47× 的字节换算常量上），而是**两个独立步进栅格的相位自由漂移**——
控制拍周期实测真抖（均值恰好 4.0000ms，但 std 0.84ms、范围 2.24~5.22ms），
而物理按固定 4ms 步进 ⇒ PWM 回读落在控制周期内的相位随机。

修法：`mcu_simulater::clock::run_one_control_tick` —— **以控制拍为唯一时基**。
`x_hover_env` / `x_hover_noise` / `x_hover_demo` 均已改；60s 全程锁相漂移 0~2ms。

**敏感度验证**（复刻 P17 的“无条件写 16B 诊断量”）：

| 配置 | max\|roll\| | max\|pitch\| | 水平 |
|---|---|---|---|
| 无锁相 + 16B 扰动（P17） | 141.90° | 87.38°（发散）| 漂 ~23m |
| **锁相 + 16B 扰动** | **9.21°** | **17.76°** | — |
| 锁相 + 无扰动 | 9.53° | 11.52° | — |
| **锁相下的 `x_hover_noise`** | **7.49°** | **11.81°** | **±2m** |

⇒ **灾难性的代码布局灵敏度已消除**（仍存二阶残余：扰动确实改变执行）；
且相位抖动原本**同时驱动**着水平漂移与极限环（23m → ±2m、49.94° → 11.81°）。

**当前 M 场剩余失败**（垂向专项，已在 H 场定位+修复，待 M 场验收）：

### 依据修正（2026-09-21 晚，实测）

上段曾把原因归为“**固件没有时序余量**”。**该归因已证伪**：

- 实测控制拍率 **249.7Hz（周期 4.005ms）**，仍达标称 250Hz；
- `zz_ctlprof` 当时打印的“单拍 5.897ms / CPU **147.2%**”是**工具常数错误**
  造成的（硬编码 `92_000` 字节/固件ms，而现场自校准实测为 **135,443**，虚高 1.47×：
  147.2% / 1.472 = 恰好 100%；而 >100% 本就物理不可能）。
- 按修正后的自校准换算重跑 `ctl_phase_breakdown`，相位合计 **4.004ms = 独立实测周期**
  （自洽✓）：

  | 项 | ms/拍 | 占比 |
  |---|---|---|
  | step_hil（含 EKF） | 0.466 | 11.6% |
  | 设定点/PWM + PWM 写 + 读帧 | 0.573 | 14.3% |
  | **计算合计** | **1.039** | **26%** |
  | `delay_until` 空转 | 2.965 | 74% |

  ⇒ **时序余量约 74%，不是“没有余量”**。工具的常数已改为**自校准**（`bytes_per_ms_calibrated`）
  以根除此类“常数过期 → 结论错误”。

**那代码布局灵敏度从哪来？** 时序余量既然充足，最可疑的是**控制周期 4.005ms ≠
物理步长 4.000ms** → 两者相位**缓慢漂移**（每拍 0.005ms，60s 漂 ~75ms ≈ 18.75 个物理步），
而 PWM 回读是每个物理步采一次 → **采样相位随代码（进而随计算耗时）而变**。
这解释了“加一条不执行的支路也会变”。**✅ 已验证并修复（`clock.rs::run_one_control_tick`）**：
以**控制拍为唯一时基**（不再让物理按固定 4ms 自成栅格），60s 全程锁相漂移仅 0~2ms。
**修后 `x_hover_noise` 60s 带噪持续悬停通过 ✓**（`max|roll| 10.26°` / `max|pitch| 13.02°`，
闸 15°；稳态水平速度 ≤0.54 m/s）。

**同时**：H 场是确定性的、迭代 <2 秒；M 场单次 ~10 分钟且结果不可信。
**两边同时调 = 两边都做不好。**

**解除条件**（满足后才恢复 M 场）：
1. H 场全部判据通过（当前剩 2 项立案：`a3` 平移残差、`2.1` 超调）
2. M 场"控制环时序余量"问题先解决（量拍率余量 + 把诊断量移出热路径）
3. 之后 M 场只做**验收**，不做探索性调试

**已挂起的 M 场待办**（不丢，但不在 H 场全绿前动）：
- 控制拍率与余量测量 —— ✅ **已完成**（2026-09-21：249.7Hz，计算仅占 26%，余量 74%；
  工具常数的错误已修）
- **控制周期 ≠ 物理步长的相位漂移** —— ✅ **已定位、已修、已验证**（2026-09-21）：
  - **定位**：亚毫秒分辨率（退休字节作时钟，量化 0.148ms）实测控制周期**真抖**：
    均值恰好 **4.0000ms**，但 **std 0.8426ms、范围 2.2439~5.2224ms**
    （直方图双峰 3.6/4.8ms；根因：`delay_until` 唤醒量化）。
  - **修法**：`mcu_simulater::clock::run_one_control_tick` —— **以控制拍为唯一时基**，
    每完成一拍才推进一次物理（PWM 总在“拍刚结束”采样，相位钉死）。
    `x_hover_env` 已改；60s 全程**锁相漂移 0~2ms**。
  - **验证**（复刻 P17 “无条件写 16B 诊断量”）：

    | 配置 | max\|roll\| | max\|pitch\| |
    |---|---|---|

    | 无锁相 + 16B 扰动（P17） | **141.90°** | **87.38°**（发散）|

    ⇒ **灾难性的代码布局灵敏度已消除**；仍有二阶残余（pitch 11.5→17.8°），

## 1. 判据归属（核心纪律）

**每个阶段的验收判据，只包含"被测模块 == 本阶段模块"的测试。**

阶段 1 = 姿态估计，所以它的判据**只含开环估计器测试**（控制器不介入、
PWM 不被消费）。一个闭环测试失败时：

1. 先定位根因在**哪个模块**；
2. 根因在控制器 → 记入对应的控制阶段，**不在估计阶段修**；
3. 根因在估计器 → 回估计阶段修，并补一条**开环**回归。

> 教训（2026-09-20）：排查 F5（磁锚 trait 委托失效）时，其影响面落在一个
> **闭环**测试（`x_hover_noise`）上，一度把该测试当阶段 1 的回归门槛，
> 一路追到 `kp_xy` / `tilt_max` / 电机饱和 —— 那是阶段 2/4 的地盘。
> 越界的连带改动（磁锚陀螺门、`realistic()` 硬铁重标）已回退，
> 详见 `docs/stage1-attitude-findings.md` F7「范围纪律更正」。

**另一条纪律：不允许为了追一个下游症状去改上游的共享配置。**
跨阶段共享的配置（`SensorConfig::realistic()`、`VehicleConfig`）的任何改动，
都必须在**改动所属阶段的判据**下验证，不能由下游症状驱动。

### §8.1 A12 磁扰动缺口（2026-09-21 实测登记）

**现象**（`att_est::a12_mag_disturb_sweep_keeps_attitude`，已 `#[ignore]`）：
```
MagDisturbSweep{rate_dps:60, bias_gauss:0.1} ⇒ RMSE 84.676° / max 179.859°  ✗ 姿态被拽翻
```

**已完成的分析（可直接执行）**：

1. **标定维度三档实测**（`mag_calibration_tiers_matter` ✓ 已落地）：
   | 档位 | 硬铁/地磁 | RMSE | max |
   |---|---|---|---|
   | 未标定·极端(120%) | 84.676° | 179.859° |
   | 未标定·典型(25%) | 15.651° | 28.642° |
   | **已标定** | **2.538°** | 7.962° |
   ⇒ **标定机制本身有效**（84.7°→2.54°）✓；缺口是**"扰动未知/变化时"的运行时拒绝** ✗

2. **修法方向（已排除一条错误路线 ✓）**：
   - ❌ **范数/模长门**：代码内已有实测否决（`why_mag_norm_gate_cannot_work`）——
     固定姿态 + 10° 倾角下 `|m|` 仅变 **±1.1%**；tol<0.02 会在噪声上乱触发，
     yaw RMSE 反而 **21.9°→24.8°** ✗。根因：**硬铁是方向误差不是模长误差**
     （`|m_world|=|Rᵀ·B+h|` 对小倾角只是二阶变化）⇒ **原理上盖不住** ✓
   - ✅ **方向类新息门**：把"磁隐含的航向"与**陀螺递推的航向**（短窗内独立且准 ✓）
     比较，残差超阈值则**拒绝该次磁锚定** ✓ —— 这是 PX4/ArduPilot 的路线 ✓
   - ✅ 参照成熟飞控：硬铁是**逐机架机体属性**（换机架/走线必变，同机架内随油门变）
     ⇒ 两家都是【离线标定 + 运行时一致性门】**两道防线** ✓（本项目的标定档已修好第一道 ✓）

3. **★ 机制查明（2026-09-21，两项实验）—— 根因不在磁扰动 ✗**：
   - **实验一：偏置扫描 + 时序**（`a12_mechanism_probe`）：
     `bias=0.00`（**完全没有扰动**）⇒ RMSE **92.128°** / max **179.752°** ✗✗
     时序形态：yaw 误差自 0° **渐进单调放大**到 ±150° 后回绕，周期与偏航速率一致。
   - **实验二：速率降到能力内**（20°/s = 0.35 rad/s，实测能力 0.2~0.5 ✓）：
     仍为 RMSE **81.534°** / max **179.966°** ✗
   ⇒ **两项均否**：既**不是磁扰动**（零偏置同样坏 ✗），也**不是速率超出能力**（降速无效 ✗）
    ⚠️ **以上两步的结论【无效】，已自我更正** —— 我的零值对照不是零 ✗：
     我把【机动的】bias_gauss 设为 0，但 realistic() 自身的硬铁 [0.3,-0.2,0.4]
     **一直在生效** ⇒ 它实为【不加额外扰动】，不是【零扰动】 ✗。
     => 教训：仪器自检必须自检到【对照值是否真为零】这一层 ✓。
   ⇒ 故【根因在机动】的结论**撤回** ✗。

### §8.1.2 ★ 修复尝试与**物理极限结论**（2026-09-21）—— 恒定硬铁飞行中不可检测

**尝试**：实现**方向类磁新息门**（`G_MAG_YAW_GATE_DEG`：磁隐含航向修正超门限则拒绝锚定），
理由是"未补偿硬铁会持续要求同向大修正（渐进拖拽）"。实测（未标定·极端档）：

| 门限 | RMSE | max | 达标<45° |
|---|---|---|---|
| 关（基线） | 81.534° | 179.966° | ❌ |
| 60° | 81.523° | 179.966° | ❌ |
| 45° | 81.551° | 179.944° | ❌ |
| 30° | 81.665° | 179.997° | ❌ |
| 20° | 139.484° | 160.991°（**更差** ✗） | ❌ |

⇒ **门完全不触发** ✗。根因（结构性，**与模长门同源**）：
```
渐进拖拽时【估计值一直紧跟被扰动的磁】⇒ 每一拍"隐含修正"只有几度 ⇒ 门永不触发；
等它变大时估计已被拖走。
⇒ 【以当前估计为预测】的磁新息门，对"被估计跟随的扰动"结构性地看不见 ✗
```
且**陀螺对照也救不了** ✗：
```
恒定机体系硬铁的【速率特征与真值一致】（偏置随机体旋转 ✓）
⇒ 只有【绝对偏置】是错的 ⇒ 陀螺只能验证速率 ⇒ 看不见 ✗
```

### ⇒ **物理极限结论**
**恒定的、未标定的机体系硬铁，在飞行中原理上不可检测** ✓ ——
- 模长门 ✗（硬铁是方向误差，`|m|` 对小倾角只二阶变化，实测 ±1.1%）
- 方向类新息门 ✗（估计跟随扰动 ⇒ 新息恒小）
- 陀螺一致性 ✗（常值偏置的速率特征与真值相同）
⇒ **唯一修法是离线标定扣除** ✓（与代码内 F7 结论一致 ✓；已实测有效：84.7°→2.54° ✓）

## 10. 推进协议

1. **单红原则**：同一时刻只允许当前阶段的测试为红。
2. **先写测试后修模块**：测试先红，再改代码到绿。
3. **禁止改阈值来"通过"**；阈值变更必须单独提交并写明依据（实测标定）。
4. **固定种子**：seed 写死在测试里；换种子 = 新 case。
5. **产物落盘**：指标表 + 关键时间序列到 `target/artifacts/<stage>/`。
6. **回归锁**：每阶段出口打标签；后续阶段不得让旧标签变红。
7. **判据归属**（§1）：不在本阶段修下游模块的问题；不为下游症状改上游共享配置。
8. **H → M**：先在 H 场跑通，再用 M 场验收；M 场只挑最狠的代表用例（7.9× 成本）。
